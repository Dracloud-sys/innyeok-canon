# 인역(人域) IP 운영 매뉴얼 v1.0

> 1인 IP 개발 조직을 위한 운영 표준. 하나의 세계관(캐논)에서 소설·게임·영상·현실무공을 파생시키고,
> AI 도구를 "생성기"가 아닌 "검증 파트너"로 운용하기 위한 구조와 규칙을 정의한다.
> **확장 원칙: 새 프로덕션 라인이 추가돼도 캐논은 불변, 파생만 추가한다.**

---

## 0. 핵심 원칙 (5줄 요약)

1. **단일 소스 원칙(SSOT):** 세계관의 진실은 캐논 레이어 한 곳에만 존재한다. 소설·게임·영상은 캐논의 "표현"일 뿐 캐논이 아니다.
2. **단방향 종속:** 데이터는 캐논 → 프로덕션 방향으로만 흐른다. 프로덕션에서 나온 설정은 승인 절차를 거쳐야만 캐논으로 역류할 수 있다.
3. **AI는 캐논을 침범하지 않는다:** AI는 프로덕션 생성과 정합성 검증만 담당한다. 캐논 변경 권한은 사람에게만 있다.
4. **git이 정합성 감사 로그다:** 캐논의 모든 변경은 커밋 이력으로 추적된다. "언제, 왜, 무엇이 바뀌었나"가 항상 답변 가능해야 한다.
5. **확장은 파생 추가로만:** 신규 라인(만화·애니·굿즈)은 프로덕션 레이어에 박스를 하나 더 붙이는 것이지, 아키텍처를 재설계하는 것이 아니다.

## 1. 아키텍처: 3레이어 구조

```
┌─────────────────────────────────────────────┐
│  [L1] 캐논 레이어 (단일 진실 공급원, git 관리)   │  ← 사람만 수정
│  세계관 원전: 법·언어·통화·노동·건축·도시·세력·역사  │
└───────────────────┬─────────────────────────┘
                    │ (단방향 참조)
        ┌───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼
┌───────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│  소설      │ │  게임    │ │ 영상/음악 │ │ 현실무공  │  [L2] 프로덕션
│ 문피아연재  │ │ Godot   │ │ 이미지·음원│ │ 체화·브랜딩│      레이어
└───────────┘ └─────────┘ └─────────┘ └─────────┘
        ▲           ▲           ▲           ▲
        └───────────┼───────────┴───────────┘
                    │ (생성 · 검증 지원)
┌─────────────────────────────────────────────┐
│  [L3] AI 도구 레이어 (Claude Code / Cowork)    │
│  생성 · 일관성 검증 · 리뷰어-퍼스트 워크플로우      │
└─────────────────────────────────────────────┘
```

### 레이어 간 규칙

| 흐름 | 허용 여부 | 조건 |
|------|:---:|------|
| 캐논 → 프로덕션 | 항상 허용 | 프로덕션은 캐논을 자유롭게 참조 |
| 프로덕션 → 캐논 | 승인 필요 | 연재 중 생긴 신설정은 "캐논 승격 리뷰" 통과 후에만 반영 |
| AI → 캐논 | **금지** | AI는 캐논 변경 제안만 가능, 직접 수정 불가 |
| AI → 프로덕션 | 허용 | 단, 생성 전 반드시 캐논 조회 선행 |

## 2. 캐논 레이어 (L1)

캐논은 **버전 관리되는 파일 저장소**다. 반드시 git으로 관리한다. 도구는 Claude Code.

### 2.1 권장 디렉토리 구조

```
innyeok-canon/                    ← git 저장소
├── SOUL.md                       ← IP의 정체성·톤·주제 (비트코인 철학 등 사상적 뿌리)
├── CANON.md                      ← 캐논 인덱스: 모든 설정 문서로의 진입점
├── world/
│   ├── law.md                    ← 법·질서 체계
│   ├── language.md               ← 언어·명명 규칙
│   ├── currency.md               ← 통화·화폐 (사운드 머니 사상 반영)
│   ├── economy/                  ← 경제 시스템 Part 1~4 (임금·경기순환·계층이동·물류)
│   │   ├── part1_wages.md
│   │   ├── part2_cycles.md
│   │   ├── part3_mobility.md
│   │   ├── part4_logistics.md
│   │   └── synthesis.md          ← 한 캐릭터 생애로 4파트 통합 (다음 작업 예정분)
│   ├── architecture.md           ← 건축·영기공학
│   ├── cities.md                 ← 도시 설정
│   ├── factions.md               ← 세력 설계
│   ├── cultivation.md            ← 수련 체계 (현실무공 4단계 프레임과 연결)
│   ├── ecology.md                ← 생물 분류·마수·침식종
│   └── history.md                ← 역사 연표
├── characters/                   ← 캐논 인물 (프로덕션 공용)
├── CHANGELOG.md                  ← 캐논 변경 이력 요약 (git 로그의 사람 읽기용 버전)
└── CONTRADICTIONS.md             ← 미해결 설정 충돌 대기열 (알려진 모순 추적)
```

### 2.2 캐논 변경 프로토콜

1. 변경은 별도 브랜치에서 작업 → 커밋 메시지에 **변경 사유** 명시 (`fix:`, `add:`, `retcon:` 접두어 사용)
2. `retcon:`(기존 설정 소급 변경)은 반드시 CHANGELOG.md에 영향받는 프로덕션 목록을 함께 기록
3. 프로덕션에 이미 노출된 설정을 바꿀 때는 CONTRADICTIONS.md에서 충돌 여부 먼저 확인
4. AI에게 캐논 검토를 시킬 때는 "수정하지 말고 모순만 지적하라"는 제약을 명시

### 2.3 정합성 감사

- **주기:** 프로덕션 라인이 캐논을 인용할 때마다 + 월 1회 전수 점검
- **방법:** AI에게 특정 프로덕션 산출물(예: 소설 최신화)과 캐논을 대조시켜 불일치 리스트업
- **산출:** 불일치는 CONTRADICTIONS.md로, 확정 수정은 캐논 커밋으로

## 3. 프로덕션 레이어 (L2)

각 프로덕션 라인은 **캐논을 참조하되 캐논을 소유하지 않는다.** 라인별 저장소/작업공간은 분리하고, 캐논은 서브모듈 또는 참조 링크로 연결한다.

### 3.1 현재 라인 명세

| 라인 | 산출물 | 도구 | 캐논 참조 규칙 |
|------|--------|------|----------------|
| 소설 | 문피아 인역-2090 연재 | Cowork (집필) | 화당 등장 설정을 캐논과 대조 후 발행 |
| 게임 | Godot RPG 인역기 | Code | 세력·수련·레벨 시스템을 캐논에서 인용 |
| 영상/음악 | 이미지 시드, Suno/Mureka 음원 | Cowork (프롬프트) | 세력 테마·비주얼을 캐논 메타데이터 기준으로 생성 |
| 현실무공 | 4단계 수련 체계 체화·브랜딩 | 수동 + Cowork | cultivation.md와 동기화, 오프라인 차별화 자산 |

### 3.2 신규 라인 추가 절차 (확장성 핵심)

새 라인(예: 만화, 애니, 굿즈, 커뮤니티, 교육 콘텐츠)을 추가할 때:

1. **캐논은 건드리지 않는다.** 새 라인은 기존 캐논을 소비만 한다.
2. 새 프로덕션 저장소/작업공간을 만들고 캐논을 참조로 연결
3. 이 매뉴얼 3.1 표에 행을 한 줄 추가 (라인·산출물·도구·참조규칙)
4. 해당 라인 전용 스킬이 필요하면 L3에 스킬 추가, **반드시 "캐논 선조회" 규칙 포함**
5. 라인이 새 설정을 필요로 하면 → 캐논 승격 리뷰 요청 (프로덕션에서 임의 확정 금지)

> 이 절차대로면 라인이 10개로 늘어도 아키텍처는 그대로다. 확장 = 표에 행 추가.

## 4. AI 도구 레이어 (L3)

### 4.1 Claude Code vs Cowork 역할 분담

**판단 기준: "git에 커밋되는가?" → 예면 Code, 아니면 Cowork.**

| 작업 | 도구 | 이유 |
|------|:---:|------|
| 캐논 문서 편집·정합성 감사 | **Code** | git 관리 대상, 변경 이력이 감사 로그 |
| Godot 게임 개발 | **Code** | 코드 저장소, godot-assistant 스킬 |
| 자동화·파이프라인 | **Code** | 스크립트/도구 코드 |
| 소설 집필·시놉시스 합성 | **Cowork** | 여러 문서 오가는 장문 지식노동 |
| 이미지/음악 프롬프트 대량 생성 | **Cowork** | 멀티스텝, 툴 여러 개 |
| 프로덕션↔캐논 대조 리서치 | **Cowork** | 문서 다수 넘나드는 분석 |
| 운영 매뉴얼·기획 문서 작성 | **Cowork** | 단, 완성본은 Code 저장소에 커밋 |

### 4.2 리뷰어-퍼스트 워크플로우 (표준 운용 방식)

이미 채택 중인 방식을 표준으로 고정:

```
1. 사람: 주제 + 제약조건 제공
2. AI:  구조/초안 생성
3. 사람: 평가 · 선별 (게이트키핑)
4. AI:  캐논과 대조하여 정합성 검증
5. 사람: 확정 → 캐논 or 프로덕션에 반영
```

핵심은 **3번(사람의 게이트키핑)**을 절대 생략하지 않는 것. AI는 생성량을 늘리는 도구이지 결정권자가 아니다.

### 4.3 스킬별 캐논 조회 규칙 (필수 적용)

기존 스킬 전부에 "생성 전 캐논 선조회" 규칙을 추가한다. 이것이 지금의 "연관성 손실" 문제를 막는 핵심 조치다.

| 스킬 | 조회할 캐논 문서 |
|------|------------------|
| `worldbuilding-innyeok` | 전체 (특히 CANON.md, CONTRADICTIONS.md) |
| `gdd-designer` | factions, cultivation, cities, economy |
| `godot-assistant` | (코드 스킬, 세계관 설정 인용 시 factions/cultivation) |
| `imagegen` | architecture, cities, factions (비주얼 메타데이터) |
| `game-character-creator` | characters, factions, cultivation |

각 SKILL.md 상단에 다음 지시문 삽입 권장:
> "생성 전 반드시 innyeok-canon/CANON.md를 조회하고, 신설정이 필요하면 확정하지 말고 캐논 승격 후보로 표시할 것."

## 5. 기존 자산 재배치 매핑표

지금 흩어진 프로젝트를 3분류로 재루팅한다. **폐기 없음 — 위치 재정의만.**

### 5.1 캐논으로 승격

| 기존 자산 | 이동 위치 |
|-----------|-----------|
| 세계관 문서 (법·언어·통화·노동·건축·도시·세력·역사) | `world/` |
| 경제 시스템 Part 1~3 | `world/economy/part1~3` |
| SOUL.md/USER.md/CONTEXT.md/MEMORY.md 시스템 | SOUL.md → 캐논 정체성 레이어로 공식화 |
| 생물 분류·마수·침식종 설정 | `world/ecology.md` |
| 현실무공 4단계 프레임 | `world/cultivation.md` (프로덕션과 양방향 연결) |

### 5.2 파생 프로덕션으로 재라벨

| 기존 자산 | 재정의 |
|-----------|--------|
| 문피아 인역-2090 연재 | 소설 라인 산출물 (캐논 소비) |
| Godot RPG 인역기 | 게임 라인 산출물 |
| 세력 음악(Suno/Mureka)·이미지 프롬프트 | 영상/음악 라인 산출물 |
| 인터랙티브 HTML 지도·레벨/세력/직업 위젯 | 영상/음악 라인의 보조 시각 자산 |

### 5.3 별도 유지 (인역 IP와 분리)

| 자산 | 처리 |
|------|------|
| `smar-pipeline` | 생명공학 커리어 트랙 자산. 인역과 무관하므로 별도 저장소 유지. "내부→외부 자산 이전" 후보로 독립 관리 |

## 6. 확장 로드맵

### 6.1 신규 프로덕션 라인 추가 시나리오

캐논이 성숙하면 아래 라인들을 3.2 절차로 순차 추가 (아키텍처 변경 없음):

- **만화/웹툰:** 소설·게임 비주얼 자산 재활용, imagegen 스킬 확장
- **애니메이션:** 영상 라인 심화, 콘티/시네마틱 메타데이터 활용
- **굿즈/커머스:** 세력 심볼·비주얼 IP 라이선싱
- **커뮤니티:** 세계관 위키 공개, 팬 참여형 캐논 주변부 확장

### 6.2 메타 프로덕션: "How To Build a One-Person Company" 라인

**인역을 만드는 과정 자체가 두 번째 프로덕트가 된다.**

- 콘텐츠 골격 = 이 매뉴얼의 구조 그대로
  1. 캐논 레이어 구축법 (AI 참조 가능한 세계관 문서화)
  2. 프로덕션 파이프라인 (단일 캐논에서 멀티 산출물 추출)
  3. 리뷰어-퍼스트 AI 운용법
  4. 현실무공을 통한 오프라인 체화·브랜딩 (차별화 지점)
- 차별점: 다른 "1인 IP" 콘텐츠와 달리 **실제 시행착오 사례(인역)**를 근거로 제시
- 도구: Cowork로 초안 → Code 저장소에 시리즈 관리

## 부록 A: 빠른 판단 플로우

```
새 작업이 생겼다
   │
   ├─ 캐논(세계관 진실)을 바꾸는가?
   │     └─ 예 → Code에서 캐논 브랜치 작업 → 커밋 → CHANGELOG 기록
   │
   ├─ 코드/게임/파이프라인인가?
   │     └─ 예 → Code
   │
   └─ 문서/집필/프롬프트/리서치인가?
         └─ 예 → Cowork (완성본은 Code 저장소로 커밋)
```
