# Obsidian 운용 가이드 — 인역 캐논 편집·열람 인터페이스

> Obsidian은 L1 캐논의 사람용 창구다. 진실은 여전히 git 저장소 한 곳(innyeok-canon)이며,
> Obsidian은 그 폴더를 여는 편집기일 뿐이다. 이 문서는 동기화 사이클과 용도별 사용법을 정의한다.

---

## 1. 최신화 (동기화 사이클)

Obsidian은 폴더의 파일 변경을 자동 감지하므로, **동기화 = git 동기화**가 전부다.
Obsidian 앱 자체는 실행 시 자동 업데이트되므로 신경 쓸 것 없다.

### 작업 세션의 표준 사이클

```
① 작업 시작 전 : git pull        ← Claude Code에 "캐논 pull 해줘" 한 마디면 됨
② 열람·편집    : Obsidian에서    ← pull된 최신 내용이 자동 반영됨 (재시작 불필요)
③ 작업 종료 시 : 커밋 + push     ← Code 세션에서 fix:/add:/retcon: 접두어 붙여 커밋
```

- **① 을 건너뛰고 편집하면** 다른 컴퓨터 수정분과 충돌할 수 있다. 편집 전 pull 습관이 핵심.
- **③ 을 건너뛰면** 이 컴퓨터에만 존재하는 캐논이 생긴다. 세션 종료 = push 완료로 정의한다.
- 여러 컴퓨터에서 쓸 경우: 각 컴퓨터에서 `git clone` 후 같은 폴더를 볼트로 열면 동일 환경.

### 커밋을 Obsidian Git 플러그인에 맡기지 않는 이유

자동 커밋은 메시지가 기계 생성되어 캐논 변경 프로토콜(변경 사유 명시, retcon 시
영향 프로덕션 기록)이 무너진다. 커밋은 Code 세션에서 사유와 함께 남기는 것이 표준.

## 2. 용도별 사용법

### 열람·탐색 (가장 큰 효용)

| 목적 | 방법 |
|------|------|
| 문서 빠른 열기 | `Ctrl+O` → 파일명 일부 입력 (예: "cult" → cultivation.md) |
| 전문 검색 | `Ctrl+Shift+F` → 설정 용어 전체 검색 (예: "영전", "각성") |
| 참조 관계 시각화 | 그래프 뷰 — 문서 간 링크 구조 확인, 정합성 감사 보조 |
| 진입점 | CANON.md를 북마크(⭐) 해두고 항상 여기서 시작 |

### 편집 (사람의 캐논 수정 창구)

- **내용 편집만** 한다. 파일명 변경·폴더 이동·삭제는 CANON.md 인덱스와 어긋나므로 금지 —
  구조 변경이 필요하면 Code 세션에서 인덱스 갱신과 함께 처리.
- 편집 후에는 Code 세션에서 커밋을 요청한다. 이때 변경 사유를 말해주면 커밋 메시지에 기록됨.
- 기존 설정을 소급 변경(retcon)하는 편집은 커밋 전에 CONTRADICTIONS.md에서 충돌 여부 확인
  (운영 매뉴얼 2.2 프로토콜).

### 신설정 초안 (승격 리뷰 대기)

떠오른 신설정을 캐논 문서에 **바로 확정 기입하지 않는다.** 초안은 별도 메모로 작성한 뒤
Code 세션에서 승격 리뷰(기존 캐논과 대조 → 사람 확정 → 커밋)를 거친다.
소설 연재나 게임 작업 중 생긴 신설정도 같은 경로를 탄다 (매뉴얼 3.2-5항).

### 하지 말 것

- ❌ 다른 위치에 새 볼트를 만들어 캐논을 복사 (SSOT 파괴)
- ❌ `[[위키링크]]` 형식 사용 — 표준 마크다운 링크 유지 (Settings → Files & Links에서
  Wikilinks 끄기, New link format = Relative path)
- ❌ pull 없이 편집 시작, push 없이 세션 종료

## 3. 운영 루틴과의 연결 (매뉴얼 7장)

- **주간** — 발행 전 캐논 대조 결과를 Obsidian으로 열람하며 사람이 게이트키핑
- **월간** — 전수 정합성 감사 시 그래프 뷰로 고립 문서(링크 없는 문서) 확인,
  CONTRADICTIONS.md 미해결분을 Obsidian에서 검토 후 Code에서 해소 커밋
